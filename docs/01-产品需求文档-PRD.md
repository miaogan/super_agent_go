## 1. 产品概述

### 1.1 一句话定位

> 一个面向企业内部的 **AI 智能体（Agent）应用后端平台**：统一提供用户与权限体系、多模型 LLM 能力网关、可编排的智能体服务，以及 **RAG 知识库检索增强**能力，业务方通过单一网关即可快速构建自己的 AI 应用。

### 1.2 背景与问题

企业内各业务线在做 AI 应用时普遍面临五类重复投入：

| 痛点 | 具体表现 |
|---|---|
| **重复造轮子** | 每个业务各自对接 GPT/DeepSeek/通义，重复处理密钥、重试、限流、计费 |
| **模型难切换** | 模型价格与能力快速变化，业务与厂商 SDK 深度耦合，切换成本极高 |
| **账号体系割裂** | 各自实现登录、Token 校验、配额管理，安全水位参差不齐 |
| **Agent 难落地** | 缺少统一的工具调用、多轮上下文、会话持久化能力，业务方从零自研 |
| **知识库各自为政** | 每个业务自行搭向量库、写文档解析、调 Embedding，重复投入且效果参差；文档格式五花八门，解析质量无人把关 |

### 1.3 产品目标

| 目标类型 | 具体指标 |
|---|---|
| **业务目标** | 业务方接入 AI 能力的平均工期从 2 周缩短至 **2 天** |
| **技术目标** | 支持模型热切换；单模型故障可自动降级；网关层 P99 延迟 < 50ms（不含模型推理） |
| **运营目标** | 统一的 Token 计量与配额管控，成本可追踪到业务线 / 用户 / 应用维度 |
| **规模化目标** | 支撑 100+ 业务应用接入，日调用量百万级 |

### 1.4 目标用户

| 角色 | 诉求 |
|---|---|
| **业务研发工程师** | 通过一套统一 API 快速接入 AI 能力，无需关心模型差异 |
| **AI 应用开发者** | 需要 Agent 编排、工具调用、RAG 检索、会话管理等高级能力 |
| **平台运维 / SRE** | 需要统一的可观测性、限流熔断、灰度发布能力 |
| **业务负责人 / 财务** | 需要 Token 消耗与成本分摊报表 |

### 1.5 核心使用场景（User Story）

1. **作为**业务研发，**我希望**只申请一个 API Key，就能调用平台内所有已授权的模型，**以便**不必逐个厂商开通账号。
2. **作为**AI 应用开发者，**我希望**把公司内部的查询接口注册成工具，让 Agent 自主调用，**以便**快速构建企业知识助手。
3. **作为**运维，**我希望**在某个模型服务商故障时平台自动降级到备用模型，**以便**业务无感知。
4. **作为**业务负责人，**我希望**看到本业务线的 Token 消耗趋势与成本明细，**以便**做预算控制。

## 2. 产品范围

### 2.1 本期范围（V1.0）

- ✅ 用户注册 / 登录 / JWT 鉴权 / RBAC 权限
- ✅ 统一网关：路由转发、鉴权、限流、聚合
- ✅ 多模型统一接入（OpenAI 兼容协议）+ 模型路由与降级
- ✅ 同步对话 + 流式（SSE）对话
- ✅ Agent 会话管理、多轮上下文、工具调用
- ✅ **RAG 知识库：文档解析、切片、向量化、语义检索、引用溯源**
- ✅ 全链路可观测（Trace / Metrics / Log）
- ✅ 服务注册发现与配置中心（Nacos）

### 2.2 非本期范围（V1.x 规划）

- ⏳ 可视化 Agent 编排画布
- ✅ 混合检索（向量 + 关键词 RRF 融合 + 网络检索来源）+ Rerank 重排模型
- ⏳ 多模态 Embedding（图文混合检索）
- ⏳ 多租户计费与在线支付
- ⏳ Agent 市场与分享
- ⏳ 多模态对话（图片 / 语音 / 视频）

### 2.3 明确不做

- ❌ 自研大模型（只做接入与编排）
- ❌ 模型训练与微调平台
- ❌ 面向 C 端用户的直接产品
- ❌ **不将模型接入能力耦合进业务服务**（`llm_service` 保持独立网关定位，见 [ADR-002](./06-架构决策记录-ADR.md)）
- ❌ **不将 RAG 能力耦合进 `agent_service`**（`rag_service` 保持独立，见 [ADR-007](./06-架构决策记录-ADR.md)）
- ❌ **不支持加密文档与无文字层扫描件的解析**（需 OCR，V1.x 再评估）

## 4. 关键业务流程

### 4.1 用户登录流程

```
用户 → gateway → auth_service
                    ├─→ user_service: 查询用户（按手机号/邮箱）
                    ├─ 校验密码（BCrypt）
                    ├─ 生成 AccessToken + RefreshToken（JWT）
                    └─→ Redis: 缓存 Token 状态
         ← 返回 Token 对
```

### 4.2 流式对话流程（核心链路）

```
客户端 ──POST /api/v1/agent/chat/stream──▶ gateway
                                            │ 1. 校验 JWT
                                            │ 2. 限流检查
                                            ▼
                                      agent_service
                                            │ 3. 校验会话归属
                                            │ 4. 加载上下文（Redis）
                                            │ 5. 组装消息列表
                                            ▼
                                      llm_service
                                            │ 6. 路由选模型
                                            │ 7. 配额校验
                                            │ 8. 调用 LLM（Eino ChatModel.Stream）
                                            ▼
                                      外部 LLM API
                                            │ 9. 逐 chunk 返回
                                            ▼
                                      llm_service ── 10. 累计 Token 用量
                                            ▼
                                      agent_service ── 11. 落库 + 更新上下文
                                            ▼
                                      gateway ──SSE 透传──▶ 客户端
```

### 4.3 模型降级流程

```
llm_service 调用主模型 → 失败/超时（阈值可配）
        ├─ 记录失败计数到 Redis
        ├─ 判断是否达到熔断阈值
        ├─ 是 → 切换备用模型（按模型优先级列表）
        └─ 仍失败 → 返回统一错误码 50301（模型服务不可用）
```

### 4.4 文档入库流程（RAG 写入链路）

```
客户端 ──POST /api/v1/rag/kbs/{kb_id}/documents──▶ gateway
                                                    │ 1. 校验 JWT + kb:write 权限
                                                    ▼
                                              rag_service
                                                    │ 2. 校验知识库归属
                                                    │ 3. 计算 file_hash，查重
                                                    │    ├─ 命中 → 直接复用已有 chunk，返回
                                                    │    └─ 未命中 ↓
                                                    │ 4. 原始文件存对象存储
                                                    │ 5. 写入 documents（status=0）
                                                    │ 6. 返回 doc_id（异步处理）
         ◀── 202 Accepted ──────────────────────────┘
                                                    │
                          （后台异步流水线，见 §4.5）
```

### 4.5 文档解析与向量化流水线（异步）

```
documents.status: 0 待处理 → 1 解析中 → 2 已完成 / 3 失败

解析中：
  ① Eino Loader 按 file_type 解析 → 纯文本 + 结构信息
  ② Eino Splitter 切片（recursive/markdown/semantic）
  ③ 写入 PG chunks（vec_status=0）★ 此刻内容已可查
  ④ 分批调用 llm_service.Embed()（batch=16，Redis 缓存命中则跳过）
  ⑤ 写入 Milvus 拿到 pk → 回填 chunks.milvus_pk, vec_status=1
  ⑥ 更新 documents.status=2 与 knowledge_bases.chunk_count

失败：记录 error_msg，状态置 3，支持手动重试
兜底：补偿任务每 5 分钟扫描 vec_status<>1 的陈旧记录并重放
```

### 4.6 RAG 增强对话流程（核心链路）

```
客户端 ──POST /api/v1/agent/chat/stream（携带 agent_id）──▶ gateway
                                                            │ 1. 校验 JWT + 限流
                                                            ▼
                                                      agent_service
                                                            │ 2. 校验会话归属、加载上下文
                                                            │ 3. 读取 Agent 配置（含 kb_ids）
                                                            ▼
                                                      rag_service
                                                            │ 4. 调 llm_service.Embed(query)
                                                            │ 5. Milvus ANN 检索 top-20
                                                            │    filter: kb_id in (白名单)
                                                            │ 6. 回 PG 取 chunk 原文（20 条）
                                                            │ 7. 重排 → 阈值过滤 → top-5
                                                            │ 8. 上下文外扩（仅 top-5）
                                                            ▼
                                                      agent_service
                                                            │ 9. 拼装 Prompt（tpl_rag_qa）
                                                            │    【参考资料】[1]...[5] + 用户问题
                                                            ▼
                                                      llm_service → 外部 LLM API
                                                            │ 9. 逐 token 返回
                                                            ▼
                                                      agent_service
                                                            │ 10. 解析答案中的 [n] 引用
                                                            │ 11. 落库消息 + cited_chunk_ids
                                                            ▼
                                                      gateway ──SSE──▶ 客户端
                                                            （含引用来源信息）
```

**降级分支（Milvus 不可用时）**

```
检索失败 / 熔断打开
   ├─ ① 尝试 PG 关键词检索（chunks 全文/trgm）
   │      └─ 有结果 → 继续流程，响应标注 degraded: true
   ├─ ② 关键词也无结果 → 上下文置空
   │      └─ 走纯 LLM 对话，响应标注 degraded: true
   └─ 用户可见提示：「知识库暂时不可用，已降级为普通对话」
```

> **关键产品决策**：RAG 检索失败**不让整个请求失败**。用户仍能得到回答（只是可能不够准确），并收到明确提示。可用性优先于答案完备性——详见 [02-技术架构设计.md §7](./02-技术架构设计.md)。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 |
|---|---|
| 网关层额外延迟（不含模型推理） | P99 < 50ms |
| RPC 内部调用延迟 | P99 < 10ms |
| 模型首 Token 延迟（TTFT） | 取决于厂商，平台不额外增加 > 200ms |
| 单实例 QPS（网关） | ≥ 10,000 |
| 并发流式会话 | ≥ 1,000 / 实例 |
| **向量检索延迟** | **P99 < 500ms（含 Embedding 调用）** |
| **Milvus 单次 ANN 检索** | **P99 < 200ms（1000 万向量规模内）** |
| **单文档解析吞吐** | **≥ 100 页 / 分钟（PDF，单 worker）** |

### 5.2 可用性

| 指标 | 目标值 |
|---|---|
| 服务可用性 | 99.9%（月度） |
| 故障降级时间 | < 3s（自动切换备用模型） |
| 服务优雅退出 | 支持，等待存量请求完成（Kitex ExitWaitTime 可配） |
| **RAG 降级可用性** | **Milvus 故障时，问答服务仍可用（降级为纯 LLM，成功率 ≥ 99%）** |

### 5.3 安全

- 密码 BCrypt 加盐哈希存储，禁止明文
- 所有对外接口强制 HTTPS
- JWT 签名使用 RS256，密钥由 Nacos 配置下发并支持轮换
- API Key 加密存储，展示时脱敏
- 敏感配置（LLM API Key）通过 Nacos 加密配置管理，不落代码库
- 全量接口访问日志留存 ≥ 90 天
- **Milvus 锁 3.0.2；9091 端口禁止对外暴露（CVE-2026-26190，CVSS 9.8）；3.0 默认 `authorizationEnabled: false` 与默认 root 密码 `Milvus` 必须显式修正**
- **知识库检索强制校验 `kb_id` 归属，禁止越权访问他人知识库**
- **文档上传做 MIME + 扩展名双重白名单校验，限制单文件大小与页数**
- **RAG 上下文与用户输入之间加明确分隔，系统提示词要求模型忽略资料中的指令性内容（防 Prompt 注入）**

### 5.4 可观测性

| 维度 | 方案 |
|---|---|
| **Metrics** | Prometheus + Grafana，采集 QPS / 延迟 / 错误率 / Token 用量 / RAG 指标 |
| **Tracing** | OpenTelemetry，全链路 TraceID 贯穿 gateway → agent → rag → llm |
| **Logging** | 结构化 JSON 日志，统一字段（trace_id / uid / service / level） |
| **告警** | 错误率、P99 延迟、模型失败率、配额超限、**文档解析失败率、向量化积压** |

### 5.5 兼容性

- **Go 1.26.x**（统一版本，禁止升级至 1.27+，原因见技术架构文档 §2.1）
- **PostgreSQL 18+** / Redis 7.x+
- **Milvus 3.0.2**（Go SDK `client/v3`；Eino 适配层自研于 `pkg/vectordb/milvus3`）
- Nacos 2.x
- 文档解析支持格式：**PDF / DOCX / HTML / XLSX / Markdown / TXT**（不支持加密文档与无文字层的扫描件）
- 浏览器：Chrome / Edge / Safari 最新两个大版本

## 7. 里程碑规划

| 阶段 | 范围 | 交付物 |
|---|---|---|
| **M1 · 骨架搭建** | 6 个服务骨架 + Nacos 接入 + 网关路由打通 | 可编译运行的服务集合、docker-compose 编排 |
| **M2 · 认证与用户** | auth_service + user_service 完整实现 | 注册登录链路可用、RBAC 可用 |
| **M3 · 模型接入** | llm_service 多厂商接入 + 计量 + 降级 + **Embedding** | 统一 Chat/Embedding 接口可用、成本可统计 |
| **M4 · Agent 能力** | agent_service 会话 + 流式 + 工具调用 | 端到端流式对话可用 |
| **M5 · RAG 能力** | **rag_service 知识库 + 文档解析 + 向量检索 + 引用溯源** | **端到端「上传文档→问答带引用」可用** |
| **M6 · 可观测与上线** | 监控告警 + K8s 部署 + 压测 + **RAG 召回评测** | 生产就绪、性能达标 |

> **M5 是新增里程碑**。之所以排在 Agent 能力之后：RAG 依赖 Embedding（M3）与完整的对话链路（M4）才能验证效果。但**基础设施（Milvus 部署）建议在 M1 就一并拉起**，避免后期补部署影响联调节奏。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型厂商 API 变更 | 服务不可用 | 统一抽象层 + 契约测试 + 多厂商兜底 |
| 流式场景下的连接泄漏 | 内存增长 | 强制超时 + 连接池 + 压测验证 |
| Nacos 单点故障 | 全链路不可用 | 生产环境 Nacos 集群部署（3 节点） |
| Token 计量不准确 | 成本失控 | 以厂商返回 usage 为准，本地估算做兜底 |
| Agent 上下文超长 | 成本上升 / 报错 | 自动摘要压缩 + 滑动窗口 |
| **Eino 破坏性更新** | 升级即编译失败 | **锁定 v0.9.21 稳定线；Adapter 隔离，业务零 Eino 依赖；裸 HTTP 薄客户端兜底（零第三方依赖，仅覆盖 Chat/Embed 子集）；升级需过契约测试** |
| **Go 版本越界至 1.27+** | Sonic 性能退回基线 | 全环境锁 Go 1.26.x，CI 与 Dockerfile 双重卡控 |
| **Milvus CVE-2026-26190（CVSS 9.8）** | 未授权访问、数据篡改、RCE | **锁 3.0.2；9091 端口网络隔离；显式开启授权并改默认 root 密码；`etcd.rootPath` 改非默认值** |
| **Milvus 3.0 回滚边界** | 启用 Storage V3 / 提升索引版本后无法回滚 2.6 | **保持 `useLoonFFI=false` 与索引版本默认；升级前必须做 etcd + MinIO 全量备份** |
| **Milvus 运维复杂度** | 引入全新基础设施，团队学习成本 | 锁 3.0.2 + 自研 `milvus3` 适配层；etcd 用 SSD；封装统一 `VectorStore` 接口；**Milvus 故障时降级为纯 LLM 对话，不作强依赖** |
| **Embedding 成本失控** | 账单飙升 | Redis 缓存（按文本 sha256）；文档 `file_hash` 去重；异步批量化 |
| **切片质量决定 RAG 上限** | 检索不准，产品价值受损 | 提供多种 splitter；**M5 阶段用真实语料做召回率评测**后再定参数 |
| **PG ↔ Milvus 数据不一致** | 检索到不存在的内容 / 漏召回 | PG 为内容真相源；`vec_status` 标记 + 补偿任务；删除靠 PG 侧过滤兜底 |
| **解析能力边界（加密/扫描件）** | 用户上传后无结果 | 明确产品提示，UI 层在上传前做格式与可解析性预检 |

## 9. 附录

### 9.1 术语表

| 术语 | 说明 |
|---|---|
| **Agent** | 智能体，能自主决策、调用工具、多轮交互的 AI 应用单元 |
| **Session** | 会话，一次多轮对话的上下文容器 |
| **Token** | 大模型计费与上下文长度的基本单位 |
| **TTFT** | Time To First Token，首 Token 延迟 |
| **ReAct** | Reasoning + Acting，模型自主推理并调用工具的范式 |
| **降级** | 主服务不可用时切换到备用服务 |
| **RBAC** | 基于角色的访问控制 |
| **RAG** | Retrieval-Augmented Generation，检索增强生成：先检索知识库，再把检索结果作为上下文交给模型生成 |
| **Embedding** | 把文本映射为高维向量的过程，语义相近的文本向量距离更近 |
| **Chunk** | 文档切片，RAG 检索的最小单位 |
| **向量检索 / ANN** | 近似最近邻检索，在向量空间中找最相似的前 K 条 |
| **HNSW** | 分层可导航小世界图，Milvus 常用的向量索引类型 |
| **召回 / 重排** | 召回=粗筛候选集；重排=精排候选集顺序，两阶段检索 |
| **RRF** | Reciprocal Rank Fusion，倒数排序融合，用于合并多路检索结果 |
| **知识库** | 一组文档及其切片的集合，是 RAG 检索的范围单位 |

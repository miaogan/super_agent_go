## 1. 测试范围与方法

本次白盒测试覆盖 Aegis 平台全部业务模块（gateway / auth_service / user_service / llm_service / rag_service / agent_service）及共享库（pkg/*），方法组合如下：

| 层次 | 方法 | 说明 |
|------|------|------|
| 静态分析 | `go vet` | 全模块静态检查，捕获不可达代码、错误格式串、锁复制等 |
| 单元测试 | `go test ./... -coverprofile` | 全量单测 + 语句覆盖率统计 |
| 逻辑分支测试 | 表驱动用例 | 对 SSRF、入库流水线、登录守卫等核心逻辑做分支级断言 |
| 边界/异常 | 故障注入 + 降级断言 | 验证 Embed 失败、维度不匹配、账号锁定、下游不可达等场景 |
| 集成（内存替身） | MemoryStore / mockstore / stub RPC | 无外部依赖跑通业务链路，避免环境噪声 |

## 9. 缺陷修复与优化记录（v1.1）

### 9.1 缺陷 #1：登录锁定防护不可达（安全防护失效）

**位置**：`auth_service/internal/service/auth.go` + `auth_service/internal/token/token.go`（LoginGuard）

**缺陷描述**：

`LoginGuard` 配置 `captchaAfter=2, maxFailures=3`。`Login` 先调 `guard.Check(username)`：

- `Check` 在 `failures >= captchaAfter` 时返回 `ErrCaptcha`；
- 原 `Login` 捕获 `ErrCaptcha` 后**直接 return**（`ErrCaptchaRequired`），不再执行密码校验，`guard.Fail()` 也不再被调用；
- 失败计数因此**冻结在验证码阈值**，永远达不到 `maxFailures` → **账号锁定防护形同虚设**。

攻击者只需面对（未强制校验的）验证码即可无限尝试，绕过了系统最强的一道暴力破解防护。修复前验证：连续失败 2 次后第 3 次起全部返回 `ErrCaptchaRequired`，失败计数停留在 2。

**修复方案**（最小侵入，保持 API 兼容）：

1. `LoginGuard` 新增 `NeedsCaptcha(username) bool`：返回是否达到验证码阈值（且未锁定）；
2. `Login` 中 `ErrCaptcha` 仅记录日志**不阻断**，继续执行密码校验：
   - 密码错误 → `Fail()` 继续累计（直至锁定），并依据 `NeedsCaptcha` 返回 `ErrCaptchaRequired` 或 `ErrInvalidCredential`；
   - 密码正确 → `Success()` 清零计数，正常放行。

修复后行为链（默认 5/3 或测试 3/2）：

| 尝试 | 修复前 | 修复后 |
|------|--------|--------|
| 第 1、2 次密码错 | `ErrInvalidCredential` / `ErrCaptchaRequired` | `ErrInvalidCredential` |
| 第 3 次起密码错 | `ErrCaptchaRequired`（计数冻结） | `ErrCaptchaRequired`（计数继续累计） |
| 达 `maxFailures` | **永不发生** | 锁定；下次尝试 `ErrForbidden` |

**回归用例**（`auth_test.go` 新增 3 个）：

- `TestLoginCaptchaRequired`：验证码提示语义保留，且提示后计数不冻结（`FailCount==2`）；
- `TestLoginCaptchaThenLock`：验证码提示后继续失败 → 第 4 次 `ErrForbidden`（锁定可达，缺陷回归核心断言）；
- `TestLoginCaptchaThenCorrectPassword`：验证码提示后密码正确 → 放行且计数清零。
